Bashou architecture

How the files fit together: the shell hook, the per-terminal companion, the bashou commands, the game data and the save. Python 3 standard library only, no third-party packages.

1. How a command reaches the pet

bashou.bash / bashou.zshSourced from ~/.bashrc. After each prompt, appends status⇥history line to the events file (builtins only, no fork) and sends SIGUSR1.
companion.pyOne background process per terminal, started with launch.py bashou.companion <shell pid>. Animates the pet, reads new events, shows bubbles.
analyze.pyTurns a command line into tools, pipes and constructs (parse_log).
progress.py + achievements.pyCounters, unlocked pets, evolutions, notifications.
state.py → state.jsonOne save shared by every terminal, behind a file lock.

→ in order, left to right. The companion also calls dialogue (what to say), behavior (what the pet does), render (half-block drawing), safety (risky commands), fight (threats) and update (the daily fetch).

bashou <command>A shell function in bashou.bash; handles on/off/here itself and passes everything else on.
launch.pySmall entry point: python3 launch.py bashou [args].
__main__.py → cli.pyargparse: help, completion, small commands. Larger commands go to their own modules through cli.run(module).
Feature moduleboard, adventure, lesson, arena, spot, transfer…

5. The game parts

Adventure (bashou/adventure/)

FileRole
game.pyThe main loop: input, events, screens.
world.pyChapters, forks, paths, checkpoints. Rules only, no drawing, easy to test.
scene.py, canvas.py, sprites.pyDrawing: the scenery, a half-block pixel buffer that redraws only what changed, the hero from behind.
quiz.pyPicks questions from questions/<lang>/<topic>.json by level, without repeats.
lessons.pyThe owl teaches a tool on the road before a fight or chest needs it.

Arena (bashou/challenges/)

challenges/__init__.py is the challenge bank; each other file is a topic (basics, everyday, grep, sed, awk, find, pipe, ps, uniq, scripting, logic, system, packages, repos, network, secrets, sql, git, cicd, code, debug, rust, security) plus trials.py for the adventure chests. fight.py runs the sandbox sub-shell, duel.py draws the fight, enemies/*.json holds the foes.

8. Architecture rules

RuleEnforced by
Imports go one way: no import cycles, even inside functions.tests/test_layers.py
Standard library only.CI step "Only the standard library"
Rules separate from drawing (e.g. world.py vs scene.py, spot/__init__ vs spot/screen).Convention; makes the rules testable
English is the source; every message goes through _().test_i18n.py, test_snapshot.py
Save shape changes bump SAVE_VERSION with a migrate() step.state.py, tests
Fights never reach the network; hints only propose installed tools.test_network.py, which.py
