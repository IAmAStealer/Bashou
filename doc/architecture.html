5. The game parts

Adventure (bashou/adventure/)

FileRole
game.pyThe main loop: input, events, screens.
world.pyChapters, forks, paths, checkpoints. Rules only, no drawing, easy to test.
scene.py, canvas.py, sprites.pyDrawing: the scenery, a half-block pixel buffer that redraws only what changed, the hero from behind.
quiz.pyPicks questions from questions/<lang>/<topic>.json by level, without repeats.
lessons.pyThe owl teaches a tool on the road before a fight or chest needs it.

Arena (bashou/challenges/)

challenges/__init__.py is the challenge bank; each other file is a topic (basics, everyday, grep, sed, awk, find, pipe, ps, uniq, scripting, logic, system, packages, repos, network, certs, secrets, sql, git, cicd, code, debug, rust, security, shellscript, whose template.sh is the script fights' starter) plus trials.py for the adventure chests. fight.py runs the sandbox sub-shell, duel.py draws the fight, enemies/*.json holds the foes.

8. Architecture rules

RuleEnforced by

12. Quality: style rules and judges

Each skill whose code players see has written rules, an agent that judges new content against them, and a test that enforces what a machine can check. Ansible has none: the owner reviews it.
